# tailzip v0.3 계획 — 복구·암호·미리보기·macOS 메뉴

상태: **계획만 작성, 구현 미착수**. 현재 기준: v0.2.0 (`2d56e36`). 아래는 제안 범위이며 우선순위와 제품 결정은 개발 전 확인한다.

## 원칙과 범위

- 손상된 압축 파일 **복구는 원본을 수정하지 않는다**. 별도의 새 압축 파일 또는 복구 폴더를 만들고 성공·건너뛴 항목 및 사유를 보고한다. 모든 손상을 고친다고 표현하지 않는다.
- 암호 **관리**와 암호 **복구 시도**를 분리한다. 암호 관리에는 OS 보안 저장소(macOS Keychain/Windows Credential Manager)를 사용하며, 명시적으로 선택했을 때만 저장한다. 저장·조회·삭제를 제공하고 설정·로그·저장소에는 비밀을 남기지 않는다.
- 암호 복구 시도는 **본인 소유 파일에 대한 로컬 후보 목록 대입**으로 우선 한정한다. 강한 암호의 임의 복원은 보장할 수 없다. 후보 수·실행 시간 상한과 취소 기능이 필요하다. 외부 서버로 전송하지 않는다.
- 이미지 미리보기는 압축을 푼 결과를 별도 폴더에 남기지 않으며, 디코딩 전 파일 크기와 픽셀 수 상한을 둔다. 비밀번호가 필요하면 기존 입력 흐름을 사용한다.
- macOS에서는 메뉴를 창 내부가 아닌 **시스템 메뉴 막대**에 놓고, 앱/파일/편집/보기/도구/윈도우/도움말 및 `⌘` 단축키를 OS 관례에 맞춘다. Windows의 기존 창 메뉴는 유지한다.
- 새 UI 문구는 한국어·영어 모두 제공한다. 기존 ZIP·7z·RAR·ALZ·EGG 동작을 깨뜨리지 않는다.

## 권장 우선순위와 완료 기준

1. **ZIP 부분 복구** (최우선): 중앙 디렉터리가 손상·유실돼도 로컬 헤더와 데이터가 정상인 저장/Deflate 항목을 찾아 별도 ZIP 또는 폴더로 복구. CRC 확인, 경로 이동·과대 확장·중복 파일명 방지, 잘못된 항목 건너뛰기. 데이터 디스크립터·ZIP64·암호화 항목처럼 안전하게 경계를 알 수 없는 경우는 사유를 적고 복구 불가로 판정한다. 7z/RAR/ALZ/EGG 전체에 일반화하지 않는다. 두 항목 중 하나가 깨진 테스트, 중앙 디렉터리 절단 테스트, 원본 불변·출력 덮어쓰기 금지 테스트를 만든 뒤 구현한다.
2. **이미지 미리보기**: ZIP/7z 등에서 선택한 PNG·JPEG·GIF(첫 프레임)·WebP·BMP를 제한된 메모리로 읽어 화면에 맞춤/확대 표시. 압축 해제·디코딩을 UI 스레드 밖에서 수행하고 잘못된 이미지/초과 크기/암호 오류를 안전하게 처리. 형식별 지원 범위는 실제 테스트로 확인해 표기한다.
3. **암호 관리자**: 아카이브별 OS 보안 저장소에 저장/사용/삭제. 기본값은 저장 안 함. 다른 파일을 같은 경로로 바꿨을 때의 암호 오적용, 저장소 잠금·권한 거부, 앱 제거 후 자격 증명 잔존을 시험·안내한다. 테스트는 사용자 실제 키체인을 건드리지 않는 대체 저장소로 한다.
4. **macOS 네이티브 메뉴**: GUI 라이브러리와 호환되는 메뉴 API로 앱 메뉴(정보·가리기·종료), 파일/편집/보기/도구/윈도우/도움말과 단축키를 연결. 언어 전환 시 라벨도 갱신. 앱 창의 메뉴를 Mac에서 중복 표시하지 않는다. 실제 macOS 번들 실행과 시스템 메뉴 막대 확인이 필요하며 헤드리스 스크린샷만으로 합격 처리하지 않는다.
5. **암호 복구 시도**: 위 저장소에 없는 암호에 대해서만, 사용자가 지정한 후보 텍스트 파일을 로컬에서 순차 확인. 정확한 후보 판별(실제 파일 내용/CRC)·취소·상한·진행률 테스트. 가능한 형식부터 열고, 헤더 암호화·형식별 API 제한은 개별적으로 명시한다. 찾은 암호의 저장은 다시 사용자 동의가 필요하다.

## 보류·결정 사항

- 복구 1차는 **ZIP의 안전한 부분 복구**만 권장한다. RAR/7z/ALZ/EGG까지 확장할지는 실제 라이브러리의 손상 파일 판독 가능성과 테스트 파일을 확보한 후 결정한다.
- 암호 복구는 후보 목록 기반을 권장한다. 무차별 대입이나 GPU 추측 기능은 이번 범위에서 제외한다.
- 암호 저장의 계정 식별은 경로를 기준으로 하되, 이동·복사된 파일에 대한 자동 암호 공유는 하지 않는다.
- 기존 v0.2.0 배포 파일을 변경하지 않는다. 구현 후 버전·패키징·배포 여부는 별도 지시를 따른다.
